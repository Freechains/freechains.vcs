# Daemon lifecycle fixes

- symptoms seen 26/09/02, all reproduced from the CLI

# Issues

## 1. partial bind HANGS instead of failing

- port busy on IPv4: git daemon warns
  `Could not bind to 0.0.0.0` but keeps serving on IPv6
- the CLI hangs half-alive; user reads it as failed
- fix: pass ONE explicit listen address, so a bind failure
  is fatal (`unable to allocate any listen sockets`)
    - `--listen=127.0.0.1`? or make it an option

## 2. stop kills only the parent

- `git daemon` forks `git-daemon --serve` per connection;
  the child INHERITS the listen socket
- a hung client (dead peer, half-open, port scan) leaves an
  orphan holding the port after `stop`
- repro: connect and stall (`exec 3<>/dev/tcp/...`), stop,
  start -> `Address already in use`
- fix: stop kills by pattern, root-specific:
  every cmdline carrying `pid-file=<root>/daemon.pid`

## 3. lingering sockets block the bind

- even with no process, a FIN_WAIT/CLOSE_WAIT socket on the
  port fails a plain bind
- fix: `--reuseaddr` at start (guide.sh already passes it)

## 4. stop: pid file removed BEFORE the kill

- a failed or slow kill leaves the daemon alive with no pid
  file: unkillable by `stop` forever after
- fix: kill first; wait until dead (`kill -0` poll, bounded);
  remove the file last; stale pid = recover, not error

## 5. start on a fresh root

- `chains/` missing -> raw git fatal `base-path does not
  exist`
- fix: `mkdir -p`, as `chains add clone` does
- start should also refuse when the pid file points to a
  LIVE daemon: `daemon start : already running`
