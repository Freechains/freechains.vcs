# Revoke: Content Revocation via Dislikes

Implements the unbuilt half of dislikes: post **REVOCATION**.
Spec: `reps.md:243-278` (Content Revocation + Block States).

## Goal

A post becomes **REVOKED** when the community dislikes it
enough.
Revocation is *display/consensus level* (Phase 1): readers and
consensus hide the payload, but the git blob stays reachable.
Physical removal ("right to be forgotten", no-retransmit) is a
later phase.

## Rule (from reps.md)

A post is REVOKED when both hold:

- `dislikes >= 3` (constant `C.dislike.min`), AND
- `dislikes > likes`

Reversible: returns to ACCEPTED when `likes >= dislikes`.

```
ACCEPTED -> dislikes >= 3 AND dislikes > likes -> REVOKED
REVOKED  -> likes >= dislikes                  -> ACCEPTED
```

## State field clash (important)

`G.posts[h].state` is already overloaded for **time
maturation** (`00-12` / `12-24` / `nil` / `beg`, see
`common.lua:154`).
Do NOT reuse it for revocation.
Add separate counters + derived flag on the post record.

Post record becomes:

```lua
G.posts[h] = {
    author, time, state, reps,   -- existing
    likes    = 0,                -- NEW: like count (n > 0)
    dislikes = 0,                -- NEW: dislike count (n < 0)
    revoked  = false,            -- NEW: derived flag
}
```

Count *events*, not summed reps
(rule is about number of dislikes, not magnitude).

```lua

    return (p.dislikes >= C.dislike.min) and (p.dislikes > p.likes)
```

depends only on final counts).
