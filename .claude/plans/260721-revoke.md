# Revoke: Content Revocation via Dislikes

Implements the unbuilt half of dislikes: post **REVOCATION**.
Spec: `reps.md:243-278` (Content Revocation + Block States).

## Goal

A post becomes **REVOKED** when the community dislikes it
enough.
Revocation is *display/consensus level* (Phase 1): readers and
consensus hide the payload, but the git blob stays reachable.
Physical removal ("right to be forgotten", no-retransmit) is a
later phase.

## Rule (from reps.md)

A post is REVOKED when both hold:

- `dislikes >= 3` (constant `C.revoke.min`), AND
- `dislikes > likes`

Reversible: returns to ACCEPTED when `likes >= dislikes`.

```
ACCEPTED -> dislikes >= 3 AND dislikes > likes -> REVOKED
REVOKED  -> likes >= dislikes                  -> ACCEPTED
```

## State field clash (important)

`G.posts[h].state` is already overloaded for **time
maturation** (`00-12` / `12-24` / `nil` / `beg`, see
`common.lua:154`).
Do NOT reuse it for revocation.
(Rename `state` -> `maturity` is a SEPARATE change, tracked in
`260721-maturity.md`.)

Post record becomes:

```lua
G.posts[h] = {
    author, time, state, reps,       -- existing
    likes = { inc = 0, dec = 0 },    -- NEW: inc = likes, dec = dislikes
}
```

- Count *events*, not summed reps (number of dislikes, not
  magnitude): each like/dislike commit bumps `inc`/`dec` by 1.
- No stored `revoked` bool: it is derived on read via
  `is_revoked(p)` (single source of truth = the counts).

Derivation helper (pure, on the post record):

```lua
function is_revoked (p)
    local L   = p.likes or {}
    local inc = L.inc or 0
    local dec = L.dec or 0
    return (dec >= C.revoke.min) and (dec > inc)
end
```

No stored flag; `is_revoked` is called on read.
Deterministic across peers (order-independent: depends only on
final counts).

## Phase 2 (separate plan)

Physical forgetting / true no-retransmit is designed in
**`260721-remove-blob.md`**.

Summary:

- Phase 1 (this plan) hides the payload; the blob still exists
  and is still transmitted on sync.
- Phase 2 lets honest peers physically drop the payload while
  keeping the consensus DAG intact — **cooperative** revocation.
- Guaranteed network-wide forgetting is **impossible** (signed,
  content-addressed, replicated DAG); Phase 2 is cooperative
  only.
- Core tension: content-addressing — `rm` keeps hashes but
  breaks serving; rewrite serves but changes hashes.
- Chosen direction: **partial clone** (`filter=blob:none`), so
  a removed blob is never read when serving; sidecar is the
  fallback.

See `260721-remove-blob.md` for the impossibility non-goal,
the serving wall, and the options.
