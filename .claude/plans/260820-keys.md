- make the cli.md "Keys:" convention true everywhere:
  string (`ssh-...`) | file path (pub or pvt, `.pub`
  sibling) | none (default `~/.ssh/id_ed25519`)
- today only `--pioneer` honors it in full

# Audit (26/08/20)

- `--pioneer`: string, pub file, pvt file, default -- OK
  (chains.lua:100-127, inline)
- `--sign`: pvt path or default (ssh.pub.key reads
  `path .. ".pub"`) -- OK, but:
    - passing the `.pub` file itself fails (`x.pub.pub`)
    - key STRING cannot sign: correct ([pub] per the table)
- `like/dislike <n> author <pub>`: STRING only
  (like.lua:33 demands `ssh-ed25519 ...`) -- GAP
- `reps author <pub>`: STRING only (direct
  `G.authors[key]` lookup) -- GAP
- tests: all author args use pre-extracted strings (PUB1,
  awk of .pub); NO test uses the path form, even for
  --pioneer
- docs: the "Keys:" table promises paths generically, but
  every example is the string form ("$(cat x.pub)"); for
  like/reps author the promise is currently FALSE

# K1: shared resolver

- factor the --pioneer resolution out of chains.lua into
  `ssh.lua`: `ssh.pub.any(v)` -> pub key string
    - `ssh-...` string -> itself (validated)
    - file, first line `ssh-...` -> pub file content
    - file otherwise -> `ssh-keygen -y` (pvt file)
    - error otherwise (caller adds the command prefix)
- chains.lua uses it (behavior unchanged)

# K2: apply to author arguments

- like.lua author target: resolve via ssh.pub.any before
  the format check
- reps.lua author key: same
- keep the trailing-whitespace trim first

# K3: `--sign` nicety
