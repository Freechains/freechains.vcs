# Goal

- make concurrent commands on one chain safe
- one writer OR many readers per chain
- no accepted action ever silently lost
- done when `race.sh` (below) shows 0 failed sends, 0 missing
  actions, 0 failed hub posts

# Evidence (26/10/05, tree-trash build installed)

- found by `/x/papers/2606-sims/p2p/race.sh`
    - hub with `daemon start --hub`
    - 8 senders x 5 posts, all `sync send` at once
    - 10 local posts on the hub at the same time
    - 3 rounds
- concurrent sends: 23 of 24 failed
- 35-41 of 50 actions missing at the hub per round
- sequential resend recovers all sender posts
- hub local posts: 2-3 of 10 fail per round
- SILENT LOSS: one hub post printed its cid, its commit
  exists (`get metadata`), but it is not in `list order`,
  even after resends
- errors seen:
    - `chain sync : malformed commit : invalid signature`
      (19 of 22 send errors)
    - `bug found : ... cannot open .../state-stdin`
    - `chain/state.lua:456: table index is nil`
    - `chain post : malformed commit : invalid signature`

# Causes

- no lock anywhere in `src/`
- shared temp files per chain (fixed names):
    - `chain/ssh.lua:140`: `allowed_signers`, written then
      removed by every verify -> "invalid signature"
    - `chain/state.lua:194`: `state-stdin` (tree-trash only)
    - `chain/state.lua:848`: `state-tmp-<i>` (tree-trash only)
    - `chain/post.lua:43`, `chain/like.lua:115`: `payload-tmp`
- HEAD moved by `update-ref HEAD <cid>` without the old value
  (no compare-and-swap)
    - `chain/post.lua:98`, `chain/like.lua:218` (main)
    - also `chain/discard.lua` and the sync merge path
    - last writer wins; the other action drops out of `main`
- readers also write: `STATE.read` stages input in
  `state-stdin` (tree-trash)
- hub hook: `pre-receive` runs `sync recv` per push, so N
  concurrent sends = N concurrent writers on one chain

# Not affected

- plain `git daemon` fetches (upload-pack): read-only
- git's own ref updates: locked, with compare-and-swap
- single-process use (the sims drivers)

# Fix 1: per-process temp files

- unique names: pid suffix or `mktemp` in the chain dir
- or no file: feed git stdin through a pipe
  (`io.popen(cmd, "w")`)
- `allowed_signers`: unique temp path passed via
  `-c gpg.ssh.allowedSignersFile=<path>`
- needed even with the lock: shared readers write temps too

# Fix 2: readers-writer lock per chain

- `flock` on `<chain>/lock`
- writers, exclusive (`flock -x`):
    - `post`, `like`, `dislike`, `revoke`, `unrevoke`
    - `sync recv` (also inside the hub hook)
    - `discard`, `sweep`
    - `chains add init|clone`
- readers, shared (`flock -s`):
    - `list`, `get`, `reps`
    - shared, not none: `sweep` and `discard` delete objects
      and `refs/states/*` a reader may still use
- `sync send`: no lock on the sender's chain (git push
  reads only); the receiver's hook takes its own lock
- implement by re-exec in `chain/init.lua`, before dispatch:
    - `flock -x|-s -w <secs> <chain>/lock`
      `env FREECHAINS_LOCKED=1 freechains <same args>`
    - `FREECHAINS_LOCKED` set: skip locking (nested calls:
      `clone` re-execs `sync recv`; the hook runs `sync recv`)
    - `-w`: a stuck holder cannot hang everyone; timeout ->
      `ERROR : chain <cmd> : chain busy`
- effect: concurrent sends queue instead of failing; a write
  is ~0.2 s, so a busy hub serializes

# Fix 3: compare-and-swap on HEAD

- `update-ref HEAD <new> <old>` at every HEAD move
- redundant under the lock, cheap insurance
- failure -> `bug found`, never a silent loss

# Order

- [ ] fix 1 (temp files): smallest, removes most errors
- [ ] fix 3 (CAS): turns silent loss into a loud error
- [ ] fix 2 (lock): makes concurrent sends queue
- [ ] check readers: a writer stores `refs/states/<cid>`
  BEFORE moving HEAD (else a reader may see a HEAD without
  its state)

# Won't do

- lock-free design (many writers merging): not needed, a
  write is short
- locking inside git daemon upload-pack (fetches are safe)
