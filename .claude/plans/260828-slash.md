# Slash Aliases: `#chat` -> `/chat`, `/comp/compilers`

- usenet-like hierarchy, but with `/` (shell-safe, no quotes)
- for now only `#` -> `/`: no `$`/`@` types in aliases
- cid loses the prefix: `<genesis>` only, never `/<genesis>`
- `chain <x>`: `x` is any path under `chains/`, so `/alias`, `alias`,
  `<cid>`, `/<cid>` all resolve; only `chains add` demands the `/`
- remote paths: `host/<alias>` and `host/<cid>` both resolve (fs)

# Layout

- `chains/<genesis>/`          bare repo (was `chains/#<genesis>/`)
- `chains/chat -> <genesis>/`  top-level alias
- `chains/comp/compilers -> ../<genesis>/`
    - intermediate dirs are plain dirs, `mkdir -p`
    - symlink target is relative, climbs one `..` per level

# Validation (`chains add`)

- alias matches `^/[%w%-%._]+(/[%w%-%._]+)*$`
    - no `//`, no trailing `/`, no `.`/`..` components
- error: `chains add : invalid alias : expected '/'`
- reject if any parent component is a symlink (would land in repo)
- reject if leaf exists as dir (alias is parent of others)
- `alias already exists` unchanged
