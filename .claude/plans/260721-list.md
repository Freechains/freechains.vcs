# List command: annotate post state (beg / revoked / normal)

Make `list` distinguish post kinds instead of printing bare
hashes, so a client can tell revoked and beg posts apart.

## Current behaviour (`list.lua`)

| subcommand   | source          | output |
|--------------|-----------------|--------|
| `list order` | `G.order`       | bare hashes (posts + likes) |
| `list begs`  | `refs/begs/`    | pending beg hashes |
| `list dag`   | `G.order`       | ASCII DAG |

Begs are ALREADY separate (`refs/begs/`), because a `--beg`
post is `reset --hard` off main and parked on a ref
(`post.lua:91-98`). Revoked posts live in `G.order` and are
detected via `is_revoked(p)`.

## Proposed suffix taxonomy

| suffix | meaning        | source            |
|--------|----------------|-------------------|
| `B`    | pending beg    | `refs/begs/`      |
| `R`    | revoked post   | `G.order` + `is_revoked` |
| (none) | normal / like  | `G.order`         |

Example:

```
a1b2c3…            (normal)
d4e5f6… R          (revoked)
99aa88… B          (pending beg)
```

## Key decision: where do the flags go?

`list order` output is likely piped/parsed as bare hashes.
Adding a suffix in place risks breaking consumers.

| option | pro | con |
|-------------------------------|--------------------|--------------------|
| A. annotate existing `list order` | one command | breaks bare-hash parsers |
| B. new mode `list order --state` / `list all` | back-compat safe | extra flag/command |
| C. two columns `<hash>\t<flag>` | machine-parseable | still a format change |

Leaning **B** (opt-in annotation) to keep `list order` stable.
Confirm before implementing.

## Should begs be merged into the annotated list?

Two views:

- keep `list begs` separate (current) and only add `R` to the
  order view; OR
- a unified `list all` that merges `refs/begs/` (`B`) with
  `G.order` (`R`/none) into one annotated stream.

Merging is nicer for a "show me everything" client but crosses
two sources (refs + order). Decide with the flag question.

Notes:

- Likes in `G.order` are never revoked -> no suffix.
- `is_revoked` lives in `common.lua` (global), available here.
- A revoked post keeps its hash in order (metadata stays); the
  flag only annotates, does not remove it.
