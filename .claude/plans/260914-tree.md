# State as a Git Tree (per-commit snapshots, per-entity files)

# Context

- today: `refs/states/<cid>` -> one blob, the whole `G` as a Lua
  chunk, one per accepted commit and sync merge
- cost per post = parse + serialize of G, linear in N
  (260829-otim.md, step 3 conclusion); 16.8k of 22.5k entries
  are tombstones nobody reads per command
- branch 260902-snapshots cut DISK (tip file + anchors every 100)
  but keeps the linear parse and gives up O(1) floors
- decision (2026-09-14): keep PER-COMMIT snapshots, store each as
  a git TREE of small Lua files; unchanged blobs are shared by hash
- supersedes 260902-snapshots (keep its sim scripts)

# Layout (DONE)

- `refs/local/<cid>` -> tree; the whole local view at that commit
    - "local": never fetched, never pushed (hook rejects other refs)
    - no `states` segment: the tip is a file, not a ref
- tree
    - `meta.lua`: now, open (no `tot`: members are eager, summed)
    - `pending/<day>.txt`: records "cid time maturity member" of
      the entries maturing that day (`time.member // 86400`), one
      per line; a bucket file dies when it empties; only dirty
      days are rewritten
    - `members/<enc(pub)>.lua`: reps, time (daily slot), dictator?
    - `order/<nnnn>.txt`: chunks of 200 cids, one per line; the
      order is append-only since the read, so only the tail chunk
      is rewritten
    - `actions/<xx>/<cid>.lua`: fanout by 2 hex chars; action,
      member, reps, revoke{member,others}, time{member,backs,apply},
      maturity
- `.lua` files are BARE table literals (`{...}`), so many load in
  one chunk; the two bulk files are plain lines: `gmatch` parses
  them several times faster than the Lua parser
- `enc(pub)`: ' ' -> '~', '/' -> '!' (reversible, no hashing)

# Cost model

- post writes: 1 action blob, 1 member blob, meta, pending, last
  order chunk; trees: `actions/xx`, `actions`, `members`, `order`,
  root -> a few hundred tree entries, independent of N
- tombstones: shared by hash, zero per snapshot
- reads per command: meta, members, pending, order tail, the
  target action of a vote; never the whole state
- floors: any cid, O(1), same reads; no anchors, no replay
- `hardfork()`: order chunks from the tail until the settled index
- `tot` in meta: maintained by apply; replaces the members sum

# API (state.lua) (DONE)

- `STATE.write(G, cid, dir?)`: `G.dirty.{actions,members}` marked
  by rules.lua at every mutation; order chunks and pending buckets
  are serialized and compared to the cached source; one
  `hash-object -w --stdin-paths`, one `mktree` per touched dir
  (deepest first), `update-ref refs/local/<cid>`
- `STATE.read(cid, dir?)`: eager meta, members, order, pending
  (one `ls-tree -r`, one `cat-file --batch`); `G.actions` lazy via
  `__index` -> `fetch`; `STATE.fetch(G, cids)` batch, `STATE.all(G)`
- listings never overwrite cached blobs/trees: the cache holds the
  newer ones during a write (the bug that ate updated entries)
- `STATE.has(cid, dir?)`: `show-ref` as today
- `STATE.dirty(G, all?)`: reset, or mark everything (genesis)
- `G.pending` records replace `ordered()`: the scans in `advance`
  read records, load an entry only when it matures or settles

# Readers to adapt

- `rules.lua`: `ordered()` and the discount scan over `pending`,
  not `pairs(G.actions)`; consolidation pops `pending`
- `consensus.lua` replay: apply per action; `winner()` sums
  members of the exclusive sets (few reads)
- `sync.lua`: `G_oct`, `G_loc`, `G_fst` via lazy reads;
  `hardfork()` on order chunks
- `list.lua`: order chunks + is_revoked per listed cid
- `reps.lua`: `actions`/`members` listings via `ls-tree`
- `like.lua`: beg-branch state preload = one action read
- `action.lua`: merge snapshot fold reads `time.backs` of backs
- `get.lua`: one action read for the revoked check
- `chains.lua`: genesis snapshot as a tree (members only)
- `sweep.lua`: gc packs blobs and trees alike; comments

# Migration

- old blob snapshots incompatible: fresh chains only
  (as with `time.apply` and the time grouping)
- `discard.lua`: drops `refs/local/<cid>` of the dropped commits
- hook `pre-receive`: unchanged (rejects everything but
  `main` and `refs/begs/*`)

# Measure

- 10k chat sim (sims/chat/chat-simple.lua, paper repo)
    - post avg vs main and vs 260902-snapshots
    - loose objects, packed size, sweep time
- fork recv at a deep floor: read cost vs anchor + replay
- run 1 (Lua-literal bulk files, every chunk rewritten):
    - 5k:  post avg 0.205s, loose 412 MB, sweep 11.7s, pack 14.6 MB
    - 10k: post avg 0.252s, loose 433 MB, sweep 15.7s, pack 34.5 MB
    - vs otim1 0.153/0.295s, otim3 0.128/0.230s
    - profile at 5k: 50ms parse + 48ms serialize per post,
      both O(N): the bulk files, not the processes
- run 2 (tail-only order, dirty buckets, line formats):
    - 5k:  post avg 0.184s, loose 349 MB, sweep 9.5s, pack 13.9 MB
    - 10k: post avg 0.210s, loose 370 MB, sweep 15.9s, pack 33.2 MB
    - beats both baselines at 10k, not at 5k (process floor)
    - profile: read gap 52ms (all pending buckets parsed), one
      `ls-tree`+`cat-file` pair per lazily fetched entry
- stage B/C (after run 2), 26 git processes per post, Lua CPU
  ~22ms per post (os.clock), the rest is process spawn + git I/O:
    - pending LAZY: the read loads the window from `min0012` (the
      oldest maturing record, kept in meta) or 13h back; older
      days load on demand (`STATE.day`); consolidation is driven
      by `members[*].head` (oldest 12-24 time) and `meta.headless`
      (unsigned begs) instead of scanning the backlog
    - entries fetched by PATH (`<ref>:actions/xx/<cid>.lua`) in one
      `cat-file --batch`, negative cache for missing cids; prefetch
      of backs + target + dedup cid in `action.lua`, of the maturing
      entries in `advance`
    - tree ids computed in Lua (SHA-1) so every tree of a snapshot
      is ONE `mktree --batch`, checked against mktree's output
    - the ref name is the tree-ish (no `rev-parse`); the ref update
      is create-only (`STATE.has` gone from the write path)
    - shard listings for the write batched in one `ls-tree -r`
- stage D (after run 3 started, not in the run): `G.order` LAZY
  behind a proxy (`__len` from `meta.order_n`, `__index` loads a
  chunk by path, `__newindex` appends); the tail chunk rides the
  eager batch; `STATE.order(G)` loads all for `list` and `hardfork`
- run 3: 50k on stage C (its 5k/10k windows are the 10k rerun),
  log `sims/chat/logs/chat-simple-50k-tree.log`, FINDINGS.md section
    - post avg per 5k window: 0.187 0.209 0.226 0.227 0.319 0.296
      0.255 0.272 0.291 0.319 (otim3: 0.128 -> 1.223; ref -> 4.98)
    - totals: 3.6h posting + 3.9min sweeping (otim3 9.0h + 4.1min)
    - loose 350-570 MB per window (13 objects/post), sweep <= 36s,
      pack 230 MB at 50k (otim3 40 MB): the per-post rewritten bulk
      files and ~6 trees per snapshot
    - 5k: post avg 0.187s, loose 349 MB, sweep 9.3s, pack 12.8 MB
    - 10k: post avg 0.209s, loose 370 MB, sweep 13.5s, pack 32.1 MB
    - uncontended profiles at 5.4k AND 10.1k: wall 0.15-0.17s, Lua
      CPU ~30ms, ~36 processes (26 git): per-post cost is FLAT; the
      window averages carry the loose-object pile (130k files per
      5k window) and the shared machine
