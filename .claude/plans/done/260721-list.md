# List command: annotate post state (beg / revoked / normal)

Make `list` distinguish post kinds instead of printing bare
hashes, so a client can tell revoked and beg posts apart.

## Current behaviour (`list.lua`)

| subcommand   | source          | output |
|--------------|-----------------|--------|
| `list order` | `G.order`       | bare hashes (posts + likes) |
| `list begs`  | `refs/begs/`    | pending beg hashes |
| `list dag`   | `G.order`       | ASCII DAG |

Begs are ALREADY separate (`refs/begs/`), because a `--beg`
post is `reset --hard` off main and parked on a ref
(`post.lua:91-98`). Revoked posts live in `G.order` and are
detected via `is_revoked(p)`.

## DECISION (2026-07-22): annotate only MIXED listings

Split on homogeneous vs mixed streams:

| listing        | content      | annotation |
|----------------|--------------|------------|
| `list begs`    | all begs     | none (homogeneous) — keep separate |
| `list revokes` | all revoked  | none (homogeneous) — NEW subcommand |
| `list order`   | mixed        | ` R` suffix on revoked |
| `list dag`     | mixed        | `~hash~` on revoked |

- Begs stay separate (`refs/begs/`), NOT merged.
- Homogeneous listings need no flag (the subcommand IS the
  filter); annotate only where the stream mixes kinds.

### Marker: `~hash~` in BOTH order and dag (2026-07-22)

Revoked entries wrap the hash in tildes (strikethrough-style) in
`list order` AND `list dag` — one consistent marker instead of
` R` in order + `~` in dag. Note: wrapping changes the hash token
in `order`, so a bare-hash parser must strip `~`; acceptable
(fetching a revoked payload errors anyway, and `list revokes`
gives clean hashes).

  marker only annotates.
