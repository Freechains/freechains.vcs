# Time errors that ABORT a sync

- winner branch (oct->rem) runs under pcall: ANY error there
  -> `ERROR("chain sync : ...")`, whole sync refused, nothing
  merges (sync.lua:136-139)
- loser branch voids only from the failure point (stderr
  warning, sync.lua:156-158): its time errors are partial

## E1: "invalid post : too old" (rules.lua:134)

- `env.time < up - C.time.diff`, up = NOW(G, act.backs)
- strict `<`: refuses at up-diff-1, accepts exactly up-diff
- the ONLY time bound, and it is a LOWER bound (no upper)
- `now` RATCHETS: entry.now = max(env.time, up), and up is a
  MAX over backs -> one future ancestor lifts up for its
  entire descendant cone
- so one `time = now+10y`, 1-rep, signed post makes every
  honest reply fail "too old"; fires inside the winner
  replay -> victim's recv ABORTS, honest branch unreceivable
- backs pinned to envelope (B7): attacker cannot dodge via
  lying backs; does not need to, one high ancestor suffices

## E2: "malformed commit : invalid time" (consensus.lua:168)

- `math.type(act.time) ~= 'integer'` (float/string/nil)
- fires BEFORE E1, also fatal on the winner side: one
  crafted action aborts the whole sync regardless of value

## E3: "chain sync : hard fork" (sync.lua:165, via :33)

- only when the remote wins
- time axis: `(new - ts[our[i]]) >= fork.time`, inclusive
- future-dated pair spanning >= 7d of FAKE time flips it
  with two posts -> fake entrenchment, then refuses honest
  reorders; refusal is by design, the INPUT ts is unclamped

## boundary table (both self-consistent)

| check    | line          | boundary | accept    | refuse      |
|----------|---------------|----------|-----------|-------------|
| skew     | rules.lua:134 | up-diff  | ==up-diff | ==up-diff-1 |
| hardfork | sync.lua:33   | fork.time| < span    | >= span     |

- the `+-1` is NOT the weakness; the missing UPPER bound is:
  up (future ancestor) and ts (future post) are both
  attacker-set and only ever clamped from below

## backdating cannot block a sync

- a LOW env.time is absorbed by max(env.time, up): no throw
- it only shifts ordering / reputation, never aborts
- sync-blocking direction is exclusively FUTURE time (E1,E3)

# Mitigation candidates (discuss)

- M1 receiver clamp: refuse `act.time > CMD.now + time.diff`
    - but sync does not read the clock today (by design:
      replay must be deterministic across peers and time)
    - a receiver-clock check is NOT replayable: the same
      commit valid today would be invalid re-replayed? no:
      re-replay only ever happens LATER, so a pass stays a
      pass; one-way gates are replay-safe
    - but hooks run on the RECEIVER: sender cannot forge
    - and local post (A1) already holds CMD.now: cheap
- M2 clamp at consensus replay: refuse when act.time exceeds
  the receiving tip's real arrival context; needs a stored
  arrival time -> breaks byte-for-byte determinism; NO
- M3 cap `now` growth instead: entry.now = max(env.time, up)
  but capped at ??? -- weakens B1's purpose; likely NO
- leaning: M1 as a pre-receive/recv gate (one-way, cheap,
  deterministic-safe), plus a local-post guard
