# Revoke: Content Revocation via Dislikes

Implements the unbuilt half of dislikes: post **REVOCATION**.
Spec: `reps.md:243-278` (Content Revocation + Block States).

## Goal

A post becomes **REVOKED** by an explicit **revoke** vote, not
by generic dislikes. Two orthogonal bipolar axes:

| axis       | positive           | negative                 |
|------------|--------------------|--------------------------|
| reputation | `like` (+reps)     | `dislike` (-reps)        |
| revocation | `revoke` (-reps)   | `unrevoke` (+reps)       |

- `revoke` uses `dislike`'s reps math; `unrevoke` uses `like`'s.
- All four cost the caster reps.
- Only the revoke axis moves the removal counter; `like`/
  `dislike` never touch revocation (no overloading).

Revocation is *display/consensus level* (Phase 1): readers and
consensus hide the payload, but the git blob stays reachable.
Physical removal is a later phase (`260721-remove-blob.md`).

## Rule

Two signed sums of the vote magnitude `T.n` (revoke `n<0`,
unrevoke `n>0`), derived on read:

- **Community** (caster != post author): `revoke.others += T.n`.
  Revoked when `others < 0` — reps-weighted net (magnitude, not
  a head count).
- **Author** (caster == post author): `revoke.author += T.n`.
  A negative `author` sum is absolute (right to be forgotten),
  forces revoked regardless of the community net. Only the
  author's own `unrevoke` lifts it.

```lua
p.revoke = { author = 0, others = 0 }
is_revoked(p) = ((p.revoke.author or 0) < 0) or ((p.revoke.others or 0) < 0)
```

Author removal is above all rules; community `unrevoke` cannot
lift a `forgotten` post.

**Reps cost:** author `revoke` (self-forget) is FREE and ungated
(no cost, no transfer, works at 0 reps). Author `unrevoke` and
all community votes cost normally. Implemented via a
`self_forget` guard in `common.lua` apply.

## Data model

`G.posts[h].state` is overloaded for **time maturation**
(`00-12`/`12-24`/`nil`/`beg`, `common.lua:154`); do NOT reuse
it. Rename `state` -> `maturity` is separate (`260721-maturity.md`).

Post record becomes:

```lua
G.posts[h] = {
    author, time, state, reps,          -- existing
    revoke = { author = 0, others = 0 },  -- NEW: two signed sums
}
```

- `revoke.author` = signed sum of the author's self votes
  (absolute); `revoke.others` = signed sum of community votes.
- No `min` constant, no like/dislike counts, no `revoked` bool.
- Both are commutative sums -> order-independent -> deterministic
  on sync replay (author check uses `T.sign == G.posts[T.post].author`).

## Phase 2 (separate plan)

Physical forgetting / true no-retransmit is designed in
**`260721-remove-blob.md`**.

Summary:

- Phase 1 (this plan) hides the payload; the blob still exists
  and is still transmitted on sync.
- Phase 2 lets honest peers physically drop the payload while
  keeping the consensus DAG intact — **cooperative** revocation.
- Guaranteed network-wide forgetting is **impossible** (signed,
  content-addressed, replicated DAG); Phase 2 is cooperative
  only.
- Core tension: content-addressing — `rm` keeps hashes but
  breaks serving; rewrite serves but changes hashes.
- Chosen direction: **partial clone** (`filter=blob:none`), so
  a removed blob is never read when serving; sidecar is the
  fallback.

See `260721-remove-blob.md` for the impossibility non-goal,
the serving wall, and the options.
