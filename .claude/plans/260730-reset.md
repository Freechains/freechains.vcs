# Goal

- Recover from a hard fork by dropping local-only history
- New command: `freechains chain <alias> reset <hash>`
- Local-only operation: no signing, no network, no reps

# Rationale

- After `sync send` fails with `hard fork`, the peer is unreachable
- Only escape: abandon local branch, take the settled one, repost
- Git backing is `git reset --hard <hash>`
- Chain state lives in-tree (`.freechains/state/*.lua`)
    - reset restores it for free
    - no cache to rebuild

# Names

- `reset`: matches `git reset --hard`
- rejected `revert`: `git revert` is additive (inverse commit)
- rejected `revert`: reads too close to `revoke`
- rejected `sync reset`: sugar over four existing commands

# Recovery flow

- `chain <alias> list dag`             -- find the fork point
- `chain <alias> reset <hash>`         -- drop local-only posts
- `chain <alias> sync recv <remote>`   -- take the settled branch
- `chain <alias> post ...`             -- repost on top
- `chain <alias> sync send <remote>`   -- back in sync

# Semantics

- `<hash>` must be an ancestor of `HEAD`
    - else `ERROR : chain reset : not an ancestor`
- unknown or non-commit hash
    - `ERROR : chain reset : invalid hash`
- `<hash>` == `HEAD` is a no-op (succeeds, prints nothing)
- resetting to genesis is allowed
- settled posts are droppable
    - hard-fork rule protects against remote reorder
    - it must not block a deliberate local escape
- prints each dropped commit as `voided : <hash>`
    - same wording as `sync recv`
    - skips `state` commits
- drops `refs/begs/*` whose post is no longer reachable
    - same cleanup as the tail of `sync recv`
