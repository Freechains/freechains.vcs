# Anonymous posts in open chains  [x] DONE

- an UNSIGNED post lands in the chain, no beg
- its cost is charged to ONE shared account per chain
- only in `open` chains (no pioneers, no dictators)

# Why

- in an open chain a throwaway key is free, so the signature
  gates nothing: unlimited signed posting is already allowed
- consensus scores a branch by the FLOOR reps of its authors:
  `winner(G_oct, ...)`, the state at the fork point
    - an unsigned commit carries no key, so it scored NOTHING:
      an anon branch weighed 0 however much it had spammed
    - a signed author in debt weighs negative
    - so anon BEAT a signed branch in debt: `0 > -500`
- one shared account fixes it: anon accumulates debt across
  every anonymous post, and any branch carrying anon actions
  weighs that debt at the next fork
- a fresh throwaway key also weighs 0 at the floor, but it is
  fresh EVERY time; only anon gets heavier

# The account

- one reserved key per chain: `C.anon = "anonymous"`
- not a pubkey: real keys start with `ssh-`, so no collision
- lives in `G.authors[anon]`, like any author
    - charged `cost` per post, consolidates, capped at `max`
    - likes to an anon post credit it back
- created on first use, as any author entry

# Substitution point

- [x] `ACTION.apply`: unsigned POST + `G.open` => `key = C.anon`
    - one substitution at the boundary
    - everything downstream is unchanged: it IS an author
    - `assert(env.sign or env.beg)` keeps holding
    - POSTS only: a vote still hits `expected signature`
- [x] `to_beg`: no edit needed, `key` is no longer nil
    - explicit `--beg` still parks, in any chain
- [x] `consensus.lua` `collect_keys`: an unsigned ACTION counts
  as `C.anon` when `G.open`, else the branch scores 0 again
    - `ACTION.is`: a sync MERGE is unsigned too, and authors
      nothing; without the guard, merges would skew the score
    - costs one `cat-file` per unsigned commit, on a path that
      already shells out per commit (see `TODO.md` P4)
- [x] `post.lua`: drop `requires --sign or --beg` when `G.open`

# Decisions

- an anon post consolidates and earns like any author
    - keeps ONE ledger rule, and good anon content repays
    - rejected: cost but never mint, which makes the account a
      pure sink, unusable after the first abuse
- self-revoke is impossible for anon (no signer to match), so
  only the community axis penalizes an anon payload
- `reps authors` lists `anonymous` like any other author
- peers agree by construction: `open` is genesis-derived, and
  the substitution reads only the genesis and the gpgsig

# Found while implementing

- an explicit `--beg` in an open chain now has `anonymous` as its
  author, where it had NONE before
    - so `advance` no longer takes the "authorless beg" branch,
      and the admission credit lands on the account
    - consistent (anon IS an author), but beyond this plan
- the 12h discount can refund an anon post INSTANTLY when the
  liker holds every positive rep in the chain (`ratio` = 1)
    - not a bug: the same rule the README shows for a pioneer
    - a test that mixes both rules reads as wrong arithmetic,
      so the anon case needs a chain of its own

# Consequences

- posting is never blocked: open chains have no gates, so the
  effect is ORDERING, not admission
- anon abuse degrades the anon channel only: the shared debt
  sinks any branch carrying those posts
- honest anon posters share that damage: an attacker can hold
  the balance negative on purpose

# Open

- a lower `max` for `anonymous` than for a real author?
- an anon post has no author to dislike: only the payload
  axis (revoke) can penalize it
- two anon posts in the same branch: the second is charged at
  the debt left by the first, which is the intent, but the
  12h discount then refunds both

# Won't do

- no anon in gated chains: admission is the point there
- no unsigned VOTES: a vote is a judgment, and one account
  would speak for every anonymous member
- no per-peer or per-IP anon accounts: Sybil-able
- no proof-of-work or rate limit as an alternative price
